# 2026-09-30 界面整理与阅读性能优化

本轮延续红白风格与现有页面架构，重点减少侧栏和阅读页的视觉负担。

## 导航

- 桌面侧栏分为阅读（今日、聚合资讯、社区广场）和创作（新闻工作台、草稿）。
- 新闻源、内容策略、自动化计划、AI 设置集中在底部「设置与工具」。运行记录与通知仍有独立入口。
- 收起侧栏后保留短文字，避免只能猜图标。
- 手机底栏保留今日、新闻工作台、社区广场、草稿、更多；通知纳入更多，避免遮挡页头按钮。
- 菜单支持 Escape、外部点击关闭及跳转后主内容聚焦。通知关闭时恢复到当前视口中可见的入口。手机视觉与键盘顺序一致。

## 页面

- 聚合资讯：平台入口改为紧凑横排，排序和搜索同排；来源状态折叠，异常数量保持可见。保留原文、来源展开、留作选题及阅读位置记忆。
- 今日：日期、采集摘要和补搜入口收紧，范围与条数归入列表标题区。首次加载不再同时显示虚假空列表。待选题默认六条、可展开其余，观察区默认折叠。
- 新闻工作台：四步流程并入页眉，收紧采集和候选工具栏、待写区与运行明细，保留现有功能。
- 社区：统一阅读字号、选中状态与操作尺寸；缺少中文速览时显示原文内容，明确区分未生成、失败、已准备状态。
- 运行记录：列表置前、诊断置后；增加文字状态与准确触发来源，将运行 ID 收入详情；窄屏使用带字段标签的卡片。

## 流畅性

首页将连续工作流通知合并为一个在途读取和一个待执行读取。初次内容不会被后台事件作废，显式刷新等待对应的新读取，卸载后不应用迟到响应。

新闻标题分类使用最多 5,000 条的进程内缓存；没有事件锚点的网址跳过重复 URL 解析。规则、事实分数和聚合结果保持不变。

在同一份 60 次运行、2,594 条候选的只读快照上，固定时间并使用独立 worker 比较，Community / Stories / Today 的完整 JSON 均一致。三次测量中位数：

| 计算 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 社区列表 | 1,392 ms | 382 ms |
| Story 聚合 | 1,355 ms | 311 ms |
| Today | 2,101 ms | 1,011 ms |

这是纯计算耗时，不是对整页加载时间的保证。后台图片补全仍可能占用计算资源。

## 验证

`npm test` 1,202 项通过；请求合并专门回归 5/5；编辑黄金集 22/22；构建与 8 项端到端流程检查全部通过。实际浏览器检查了 1,440px 桌面、1,024px 社区双栏和 390px 手机视口，修复了中等宽度导航对齐与通知图标的问题。草稿、版本、回收站、素材与交付回执的数据库片段 SHA-256 前后一致。

后台任务空闲时保存了 SQLite 一致性快照，然后重启现有本地服务；端口仍为 4317。截图与数据校验记录仅保存于本机 `.artifacts/ui-polish-2026-09-30/`，不包含在提交中。
