# 阅读与草稿交付的后续优化

本轮处理大档案拖慢阅读、交付中断后重复操作，以及手机阅读和运行记录占据过多空间的问题。延续现有红白界面和页面架构，最终发布仍由用户在平台完成。

## 阅读与性能

- 今日、聚合资讯、社区广场冷启动采用各自的读取接口，查看列表不再等待全量工作台初始化。
- 新增社区读取投影：沿用 CommunityFeed 的过期、去重、趋势和个性化规则，只返回热点、来源状态和所需偏好。刷新失败保留当前内容与筛选。
- 全局刷新合并为一次正在执行的读取与一次后续读取。操作后的调用能取得自己的新快照，不会被旧的轮询结果代替；隐藏页面停止密集轮询。
- 配图任务保留本次 Story 的来源成员，逐图读取最新图片，沿用 StoryDesk 的排序、去重与资格规则。提取原文改变 canonical URL 后重新聚合；最终证据包仍使用最新完整 Story。
- 同一实际本地档案快照的 JSON 为 17,191,847 字节，社区投影为 33,457 字节、10 条热点，逐项结果与原算法完全一致。这是数据范围对比，不是整体页面耗时保证。

## 界面与操作

- 手机及窄屏社区采用“热点列表 → 内容阅读 → 返回列表”，不同时堆叠两栏。返回保留展开数量、选择、滚动位置与焦点；未选择前不读取首篇正文。
- 运行记录默认显示 20 条，可继续查看；改变筛选重新从首批显示。诊断工具默认收起，仅展开后挂载内容。
- 移除侧栏宽度动画，修复从手机宽度切回桌面时侧栏短暂铺满页面、遮挡编辑器的问题。
- 小黑盒结果先呈现首个未完成步骤，其余明细收起，显示完成数。
- 多平台交付对未修改的稿件直接使用已保存版本，避免无谓的手动版本。新增“重试未完成的平台”，只处理明确失败或取消的已支持平台；已返回结果与结果未知的平台不自动重发。
- 仅勾选今日头条时，主操作可直接打开其编辑入口。头条仍为入口能力，没有伪装成自动填入或存稿。
- 社区成稿后的异步打开错误会显示在当前页面，保留阅读内容；不产生未处理的 Promise 拒绝。

## 小黑盒恢复

- Chrome 填入助手 0.1.26 会在尚未改写字段的登录阶段等待用户登录，并继续同一任务，最长等待 150 秒。
- 尚未获工作台确认的填入回执存入扩展本地检查点。Service Worker 重启后只补传回执，不重新执行平台填写；确认或明确终止后清除检查点。保存对象不含文章正文、图片内容或配对令牌。
- 更新文章优先使用上次标题和正文均成功、且路径可核验的官方文章编辑页，减少建立重复草稿。
- 最低兼容版本仍为 0.1.24，不新增版本拦截。已安装的扩展需要重载才能启用新增后台逻辑。

## 验证与边界

- `npm test`：1272 项通过，零失败。测试入口递归发现 server、src、chrome-extension 内的所有测试，包含过去被部分 shell 通配遗漏的根目录测试；Windows CI 沿用并发数 2。
- `npm run eval:editorial`：22/22。
- `npm run build`：类型检查与生产构建通过。
- `npm run test:e2e`：9/9。覆盖冷启动不请求全量档案、手机回位、刷新 503 保留内容、成稿后断线、运行记录分页、仅重试失败平台、未改稿不重复保存，以及 320–1920 像素布局。
- 新的侧栏缩放和成稿跳转问题均先用失败用例复现，再修复。
- 浏览器验收使用独立临时数据库与模拟平台回执，没有向真实账号发送测试文章。本轮电脑控制工具启动失败，未声称已在真实账号验证扩展 0.1.26 或头条、百家号自动存稿。
- 本地数据库已保存一致性备份；稿件、历史版本、回收站、素材和交付回执不作为开发清理对象，不进入 Git。
