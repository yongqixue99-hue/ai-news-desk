# AI 新闻台编辑器重构审计

审计日期：2026-08-11  
目标画幅：桌面端 1440 × 1024  
当前优先发布平台：小黑盒；微信公众号、小红书仅预留适配层。

## 视觉证据

- 当前编辑器：[01-current-editor.png](./audit/01-current-editor.png)
- 参考站「字间排版」：[02-reference-site.png](./audit/02-reference-site.png)
- 参考实现：[laogou717/md-wechat](https://github.com/laogou717/md-wechat)

## 结论

当前界面的主要问题不是配色或圆角，而是长期占位的导航和检查栏把写作区切得过窄。在 1440px 画幅下，214px 全局导航、264px 草稿列表和 350px 右侧检查栏同时常驻，编辑正文只剩约 600px；同时“自由编辑 / 排版预览”互相替换，无法边改边看。

下一版应从“三列后台”改成“写作工作台”：全局导航收成图标栏，草稿、资料和发布都按需出现，中间长期保留可拖动的编辑 / 预览双栏。

## 信息架构建议

### 1. 全局导航

- 收起宽度 64px，展开宽度 216px，状态持久化到本机。
- 按用户要求保留 4 个主入口：今日工作台、草稿、新闻源、自动化。
- 将“定时任务”和“运行记录”合并进“自动化”，避免为了低频页面占用一个主入口。
- 底部固定设置和头像；每个图标必须有 Tooltip、`aria-label` 和明确的选中态。
- 收起 / 展开按钮放在品牌行或侧栏右缘，支持 `⌘/Ctrl + B` 快捷键。

### 2. 草稿目录

- 不再永久占 264px；点击“草稿”图标后作为左侧抽屉出现。
- 桌面宽屏可将抽屉“钉住”，窄屏默认覆盖内容；再次点击图标关闭。
- 目录支持搜索、状态筛选、更新时间、未保存标记和键盘上下选择。

### 3. 编辑与预览

- 主工作区固定为编辑 / 预览双栏，建议初始比例 56% / 44%。
- 使用可拖动分隔条，限制编辑区最小 520px、预览区最小 360px；分隔条可用方向键调整并暴露 WAI-ARIA separator 状态。
- 保留“仅编辑”“对照”“仅预览”三种视图；“对照”是默认状态。
- 预览提供小黑盒内容宽度，并为微信公众号与小红书预留设备 / 画布预设。
- 二期可做按段落同步滚动、点击预览定位编辑段落。

### 4. 资料与发布

- 当前“来源与配图”和“填入准备”不应共用一个永久右栏。
- 右上或右下设置一个工具入口，打开 380px 右侧抽屉；抽屉内分为“资料”“图片”“发布”三个标签页。
- 发布抽屉顶部保留平台切换器：小黑盒（可用）、微信公众号（即将支持）、小红书（即将支持）。
- 小黑盒页保留社区、话题、复制排版、填入编辑器和结果回执；关闭抽屉后不影响正文编辑。

## 可借鉴的参考实现

「字间排版」的技术栈是 Vue 3、CodeMirror 6、markdown-it 和 Vite；我们的项目是 React、TipTap 和 Vite，因此不应照搬代码，但可以直接借鉴以下交互结构：

- 52px 图标 Rail + 可开合左面板。
- 图标按钮用 `aria-controls` / `aria-expanded` 描述面板状态。
- 编辑与预览之间使用可拖动、可键盘操作的 separator。
- 对照 / 预览视图切换、设备宽度预览、自动保存状态。
- 200–280ms 的结构过渡，而不是大面积装饰动画。

## 组件与技术选择

| 需求 | 建议 | 理由 |
| --- | --- | --- |
| 编辑 / 预览拖动分栏 | `react-resizable-panels` 或其 shadcn wrapper | 支持折叠、最小宽度、键盘与 ARIA separator |
| 抽屉、Tooltip、Tabs、Popover | Radix Primitives | 无样式、可访问，容易融入现有白 / 炭黑 / 朱红视觉体系 |
| 快捷操作与跨区跳转 | `cmdk` | 可做 `⌘K` 命令面板，快速打开草稿、插图、预览和发布 |
| 浮动工具条 / 图片操作 | Floating UI + TipTap 原生扩展 | 定位可靠，适合选中文本或图片后的轻量浮层 |
| 图片库排序与拖入正文 | dnd-kit（按需） | 键盘和屏幕阅读器支持比手写拖拽更完整 |
| 面板过渡 | Motion for React 或纯 CSS | 只做 140–220ms 的位移、淡入和宽度过渡 |

## 用户提供的网站如何使用

- **Origin UI / coss ui**：最值得借鉴。适合抽屉、标签页、Tooltip、按钮组、空状态和命令面板的结构参考；复制后改成现有 CSS tokens。
- **Appica UI**：适合作为可访问性和组件状态参考；不建议整库换肤，避免与当前视觉系统冲突。
- **React Bits**：只取轻量微交互，例如采集中的进度反馈、空状态或成功提示；不用于正文编辑核心区。
- **MotionSites、SceneAI、Design Prompts、Aurabuild、UI of Famous Websites**：作为界面构图和交互案例库，不作为运行时依赖。
- **NameThatUI**：用于确认组件名称和描述，方便后续给代码代理下准确需求。
- **Unicorn Studio**：WebGL2 和实时图形更适合宣传页，不适合长文编辑器；会增加 GPU、首屏和可访问性成本。
- **Thinking Orb、Border Beam、Aether CSS / Liquid Glass**：最多用于很小的 AI 运行状态或首次引导。正文、导航、发布区不使用发光边框或玻璃叠层。
- **Typography / Remotion**：可以借鉴字号层级和动效节奏，但不引入视频运行时。

## 其他值得补充的功能

1. 自动保存状态拆成“已保存 / 正在保存 / 保存失败 / 本地有冲突”，失败时允许重试。
2. 文章大纲和图片清单作为同一个可切换工具页，点击条目定位正文。
3. 图片选中后提供替换、删除、图注、宽度、对齐和替代文本，而不是只能从工具栏删除。
4. 发布前检查：标题长度、未核验事实、缺图、话题数量、外链和图片来源许可。
5. 平台适配层：统一文章数据，分别由小黑盒 / 微信 / 小红书 renderer 生成预览与复制内容，不复制三套编辑器。
6. 快捷键：保存 `⌘S`、命令面板 `⌘K`、侧栏 `⌘B`、切换对照视图 `⌘\`。
7. 响应式规则：小于 1100px 时预览和右侧工具改为抽屉；小于 760px 时底部导航 + 单栏编辑。
8. 尊重 `prefers-reduced-motion`，焦点环不得只靠颜色表达，图标按钮触控区域至少 40×40px。

## 建议的落地顺序

1. 重构全局 Rail 与四入口导航。
2. 将草稿目录、资料 / 图片、发布改为独立可开合面板。
3. 加入编辑 / 预览可拖动双栏与三种视图。
4. 完善快捷键、焦点管理、响应式和自动保存状态。
5. 最后再添加同步滚动、文章大纲和轻量动效。

## 限制与风险

- 参考站当前以 Markdown + CodeMirror 为核心，我们已经使用 TipTap 富文本；只复用布局和交互，不切换编辑内核。
- 右侧发布栏若使用 modal drawer，会遮挡预览；桌面端应使用 non-modal sheet 或可钉住面板，并保证焦点返回触发按钮。
- 同步滚动需要稳定的段落 ID，不能依靠像素比例，否则长图和异步图片加载会造成跳动。
- WebGL、持续光效和大面积毛玻璃会降低长文阅读清晰度，也会增加低端设备功耗，暂不纳入编辑器。
