# AIHOT 第一批吸收：聚合阅读与采集可靠性

日期：2026-09-29。依据 [源码复用审查](research/2026-09-29-aihot-reuse.md)，在新闻台现有模块内实现四项改进。外部参考固定于 [AIHOT 589f79e](https://github.com/KKKKhazix/AIHOT/tree/589f79eff09470b31ba8a7f1d9eb62d36ff2be6c)；本轮独立实现适配，没有复制其源码、引入其数据库或执行其服务。

## 用户能看到的变化

1. **事件更容易读。** AIHOT 热榜事件显示有来源标识的“事件摘要”和“最新进展”。长摘要默认折叠为四行，可展开；报道、收录来源数量、更新时间和推荐依据放入同一个折叠区。缺少事件字段时仍显示原有摘要。
2. **返回后接着读。** 离开聚合页再回来，保留平台、栏目、搜索词、加载数量、展开的摘要和报道，以及阅读卡片的位置。刷新仍读取服务器当前数据，会话中只保留阅读偏好和位置，最长 30 分钟。
3. **慢来源有退出时间。** 请求截止时间覆盖 DNS、重定向和响应体，取消信号传入正文和图片探测。采集通道、单篇提取、提图阶段分别有截止时间；一个通道卡住时，已经完成的其他通道结果可以留下。阶段超时后阻止迟到的提图结果写回本轮状态。
4. **新速读少犯主体和类型错误。** 生成的中文速读不能凭媒体署名新增已知公司主体，也不能把原文教程、指南、测评改成纯产品发布标题。单条不合格时保留同批合格结果，记录原因，不改动用户已编辑的草稿。

## 实现边界

- `aggregation-event.ts` 负责事件字段与报道 URL 的读取、长度限制和去重；`structured-collector.ts` 将事件字段从上游解析结果一路带到本地聚合快照。解析缓存版本已更新，旧的 304 缓存不会让新字段永久缺席。
- `reports` 是事件报道；`related` 与 `storyline` 不当成同一事件强行合并。“收录来源数”只描述 AIHOT 收录量，不增加本地事实可信度。
- `useAggregationReading` 管阅读位置；React 页面只负责展示和交互。保持现有红白界面和导航结构。
- `abort.ts` 为不可直接取消的等待提供有界返回；操作系统 DNS 本身可能仍在结束过程中。共享网络边界保留原有地址检查。默认网络请求 20 秒、单篇提取 30 秒、整段提图 60 秒、采集通道 180 秒。
- 通道隔离沿用结构化来源、社区、X 三组；本轮未把每一个来源都改成独立持久队列。
- `briefing-grounding.ts` 是有限的公司别名与文章类型检查，不是完整事实核验。原有 `ContentPackage`、草稿质量门、图片来源与交付校验继续负责各自范围。

## 验证

- 回归先复现，再修复：DNS 不响应、读取半截响应体、取消中的提取、慢通道不结束、无依据公司主体、教程变发布，以及事件字段在采集适配层丢失。
- `npm test`：1192 / 1192 通过。
- `npm run eval:editorial`：22 / 22 通过。
- `npm run build`：通过。
- 聚合浏览器回归：1440 和 390 宽度无横向溢出；长摘要折叠与展开、最新进展搜索、返回后筛选及卡片位置恢复通过；普通浏览不产生写入请求或 AI 调用。
- 真实 AIHOT 接口经完整采集链路读取 210 条内容，其中 10 条事件具备摘要和最新进展，失败路由为 0。该次检查证明链路和字段可用，不代表上游内容已完成事实核验。
- 本机应用已重新构建并加载新版本，聚合接口实际返回 10 条事件。更新前做了本地 SQLite 一致性备份；更新后对草稿、版本、回收站、素材和发布回执五类数据计算摘要，均与更新前一致。备份和截图仅保存在忽略目录 `.artifacts/`。
