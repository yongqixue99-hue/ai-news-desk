## 实现与使用入口

| 项目 | 实际行为 | 主要文件 |
| --- | --- | --- |
| C1：漏报定位 | 运行记录输入原文链接，只查本地逐条路径：原始日期、关键词、去重、评分、合并、数量限制、当前材料/推荐状态。新采集完成时记录推荐快照，可查首次记录进入推荐的时间。 | `discovery-funnel.ts`、`discovery-trace.ts`、`horizon.ts` |
| C1：全局证据 | 平台筛选仅裁展示结果；同事件的官方/其他来源保留在全局证据池。合并后不展示的来源仍可被显式选择用于速读/成稿，默认模型工作量不扩大。 | `community-feed.ts`、`topic-feeds.ts`、`story-desk.ts`、`candidate-pool.ts`、`package-desk.ts` |
| C1：热度 | 缺失与实测零分开；按平台、帖龄和观测字段组成比较组，至少 5 条才计算百分位。增量只用相邻有效观察；缺失恢复、过长间隔、负增量不伪装为增长。全局新闻排序不再复用未校准的社区积分。 | `community-metrics.ts`、`community-feed.ts`、`scoring.ts` |
| C2：实践选题 | 必须有具体实践和可回链材料，展示用途、读者、稿型及未实测限制；30 天有效期，使用独立于新闻时效的资格门槛；同一可识别作者只占一个实践推荐位，无作者时回退到来源身份。明确日期范围、未知日期和未来日期仍优先约束。 | `practice-opportunity.ts`、`story-desk.ts`、`StoryReader.tsx` |
| C2：健康 | 运行记录分别展示连接、解析、候选供给、原文读取状态。没有候选或没读原文不能被“连接成功”覆盖。 | `source-health.ts`、`RunsPage.tsx` |
| D1：正文结构 | 生成可表达标题、段落、列表、表格、代码、引用；解除 8 段/索引 7 的限制，按实际正文长度验证事实及图片索引。资源上限为 200 块/10 万字，不等同于建议写满。代码保留缩进，表格使用完整 TSV，非法表格报错。 | `article-blocks.ts`、`generator.ts` |
| D1：关系检查 | 增加价格起终点、比较对象和方向、套餐范围、型号版本、否定及明确条件反例；数字必须属于被引用的型号。文末判断也检查量化事实。 | `fact-relations.ts`、`frozen-fact-integrity.ts`、`editorial-quality-desk.ts` |
| D1：当前版本 | 核对实际可见 HTML；旧段落数组和旧事实映射不能替改过的文字背书。“资料 → 当前版本核对”支持明确选择冻结事实重绑正文。检查绑定正文/事实/图片/素材包，AI 建议遇到这些变化失效。 | `draft-check-binding.ts`、`draft-quality-review.ts`、`draft-document.ts`、`DraftQualityPanel.tsx` |
| D1：来源变化 | 比较本地新快照与冻结原文，列出受影响稿件和事实；不自动改包或改正文。核对结论绑定确切正文、素材包和新来源哈希，之后修改会失效，决定随历史版本保存。 | `source-change-impact.ts`、`draft-revisions.ts`、`SourceChangeImpactPanel.tsx` |
| D2：图文检查 | 已知三张问题图按指纹/原始地址命中图注、条件、案例约束；自动选图排除不合格项，人工插入也检查当前段落/图注。交付时继续检查目标平台权利、本地文件与事实状态。 | `visual-context.ts`、`draft-visual-check.ts`、`editorial-image-policy.ts` |
| D2：实际返工 | “版本 → 记录实际返工”保存真实原因、当前修订、可选人工分钟数。空时间存为未知，重复提交幂等，不从机器耗时推算人工耗时，也不直接写入表达学习。 | `edit-observation.ts`、`EditObservationForm.tsx` |

保留瑞士红白风格、平台栏目、自定义关键词栏的原含义。未新增来源：此前两条作者订阅仍应先取得真实供给与可读性观察，再按缺口扩源。微信最后提交前重查当前正文、材料和来源状态；新建、更新、未变化重试都有拦截回归。生成版本升为 `package-boundary-v16`，旧尝试留在历史。
