# D4 前端拆分边界（待用户决定）

本轮先完成server/index.ts的126个API路由按11个领域独立PR拆分。DraftWorkspace.tsx和App.tsx的行为拆分建议单独验收后推进；它们承担用户编辑状态，不能用后端机械搬迁方法处理。

实测：DraftWorkspace.tsx 2052行/116049 B，App.tsx 1524行/58437 B；App内26处refresh()调用。按当前源码逐行审查，关键耦合如下：

- DraftWorkspace第469行save：activeSaveRef串行化；editingRef/编辑版本/请求正文快照/持久更新时间共同确认回包是否仍属于当前文章和修改。切换草稿、自动保存（1100ms）、页面关闭恢复、管理操作都等待同一保存。分散到多个hook可能改变执行顺序，使迟到回包覆盖后续修改或误清除恢复快照。
- 第574行页面退出保存：先等已有保存，再按当前draft id和editVersion清理localStorage，卸载清理函数仍会执行。把子组件卸载等同整个编辑器卸载会误触发保存。
- 第614行起历史/AI/图片加载通过active标记拒绝迟到响应；第700行交付轮询把draft id和updatedAt绑定回执。拆分必须保留身份绑定、排他锁、原事实/图片权限检查和精确补丁，不能新增最终发布行为。
- App第82行refreshQueue一次加载bootstrap/editorialSystem并同步Shell、activeRunId、activeDraftId；26处动作刷新共享该队列。选题生成、快速收录、导航、草稿恢复相互联动，多个局部刷新队列可能让旧响应覆盖新选择。

建议下轮：先拆纯展示的草稿库/图片/版本面板（父组件仍持有保存与编辑身份）；随后单独提取保存协调器，先覆盖保存中切稿、双连续修改、卸载与重挂、回执迟到、AI精确补丁和恢复快照。App先拆领域动作适配器，再评估刷新生命周期，保留单一队列。
