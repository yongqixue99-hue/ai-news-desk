# C4 聚合标题翻译提案

独立基于 main c65c069。等待用户决定，不合并、不上线；未叠加 C2/C3 的未批准代码。本项涉及聚合浏览规则和新增缓存表，需要明确决定后才能上线。

默认浏览、过滤、切平台和刷新只读取已经存在的缓存，模型调用为 0。“翻译本页标题”由用户手动触发，按当前平台、频道、查询及已展开的列表范围选取最多 20 条尚无中文的标题。缓存命中不再次调用模型。不会翻译隐藏页面或其他频道。

中文显示在上方，原题和“机器翻译”标记保留在下方；原文链接原样。模型和翻译时间保存在缓存，标记悬停可见。搜索、排序、留作选题、事件合并、事实核验和原始记录始终使用原题，译文只用于显示。切换列表后的迟到响应不得显示到新列表，旧缓存读取不得覆盖刚完成的手动结果。

新表 `title_translations(key,title_zh,model,translated_at)`：键为完整原题与链接 JSON 元组的 SHA-256，大小写与空白也保留。schema 6→7 为新增表，旧库中的状态逐项不变。完整 SQLite 归档保留缓存；导入无此表的 schema 6 快照时清空衍生缓存并保持旧状态。轻量 JSON 备份仍包含原始状态，缓存可重新生成。

服务端在模型前验证当前快照的 ID、原标题和链接，拒绝未知、重复、过量或已变化条目；模型完成后再检查快照。缺失、重复、未知 key、非中文、未知字段或错误模型身份均整批拒绝，0 条缓存写入。同一个缺失键共用正在运行的请求；失败不自动重试或换模型。

沿用配置中的分析模型及原有回退选择，不设置 modelOverride。保留 X/Gemini 零新增支出规则，在真实缺失批次才检查模型与费用设置；缓存命中不需要模型配置。任务数据明确是外部不可信标题，仅做翻译；临时 schema/output 全部清理，不写 `.workflow/`。本轮全部使用注入的假模型，真实模型耗时、质量和费用未实测。

切换页面或平台会丢弃迟到显示响应；已经由用户开始的批次可完成并缓存，不会因此发起新批次或重复请求。需要用户决定是否接受这个手动入口及将来的现有分析模型调用费用。
