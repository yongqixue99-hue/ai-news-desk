# AI 新闻台成熟个人版

## 产品边界

这是单用户、Windows/macOS、本地优先的 AI 科技编辑工作台。它帮助个人创作者从新闻与社区信号中决定“今天写什么”，把核验后的事实、原句和图片组织成公众号图文草稿。它不做自动群发、不替用户点击最终发布，也不把证据不足的社区热度写成新闻事实。

## 默认生产链路

```text
SourceDesk.collect
  → StoryDesk.ingest
  → 今日推荐 / 人工选题
  → EditorialDesk.assign
  → PackageDesk.build
  → DraftDesk.create
  → 人工编辑与预检
  → DeliveryDesk.sync(wechat)
  → 用户在微信后台发布
  → LearningDesk.record
```

写稿阶段只能引用 `ContentPackage` 中已经冻结的证据。素材包保留事实支持、冲突来源、社区作者与永久链接、图片来源与权利状态，以及当前不知道的内容。证据不足时停在 `Watch` 或 `Skip`。

官方教程、工程文章与技术实践进入独立技术待选库，不套用普通新闻的 48 小时淘汰规则，不虚构发布日期。默认忠实整理官方结构、步骤、代码、表格和原图；复杂文章降低优先级并提供通俗导读。技术资料仍需读取原文并冻结素材才能成稿。

小黑盒兼容交付可选择文章或图文图集。图集独立选图排序，切换形式保留文章原有配图位置；单次填入串联保存、预检、图片上传、分区及话题核对。失败显示具体步骤和回执，不自动点击最终发布。

## 日常使用

首页默认 AI 新闻，主栏可切换知乎、Hacker News、V2EX、GitHub。社区分类独立保留来源和互动单位，GitHub 已采集项目与实时 Trending 分开标识。浏览分类不请求 AI；右侧“我的待选题”保留用户明确选择且尚未成稿的事件，不受今日推荐窗口影响。榜单未连接和旧快照必须如实显示。

1. 打开“今日”，默认精选重要变化，并为有趣、有用的实践留最多 2 个位置；主推荐最多 3 条，总推荐最多 8 条，数量不足时保留空位。常规动态可在全部候选中查看，也可切换广泛浏览。中文标题、发生了什么、为什么重要、社区观点、趋势、证据与图片数量都在卡片上。若明确知道想追的模型、公司或事件，可直接搜索最近 7 个香港自然日的官网与新闻来源；这条事实搜索不读取 X 或社区帖。
2. 打开 Story 详情，核对官方／新闻／社区来源、事实、冲突和视觉证据；选择稿型并生成素材包。
3. 素材包通过后生成草稿。编辑器会把原文图表、产品界面或相关截图放进对应段落，而不是只存入图片托盘。
4. 在“资料、图片、版本、发布”中核验事实、版权、排版和版本。去 AI 味只给出局部补丁，不能覆盖用户已经修改的全文。
5. 在“发布”中同步公众号草稿箱。首次创建、后续更新同一个 `media_id`；系统从不调用群发接口。

普通新闻以 48 小时为今日推荐窗口。已知模型厂商官网确认、发布状态明确且证据可用的正式模型发布可在 7 天内补回，避免重要发布因预告与正式发布日期错位而永久漏报；这项例外不能用于普通旧闻。
6. 用户在微信公众平台预览并发布后，回到工作台确认发布。只有此时才会记录有效编辑差异和沉淀授权合格图片。

公众号接口未配置或暂时不可用时，可以从同一个发布面板复制已经内联样式的公众号排版，再手动粘贴到公众号编辑器。这是交付备用通道，不会创建草稿、调用群发接口或确认发布。

## 社区证据门槛

- 少于 5 条有效评论：只能写“有限样本中有人提出”。
- 5–14 条：可以列观点，不能声称多数或共识。
- 至少 15 条且覆盖 5 个独立讨论分支：才允许提炼反复主题。
- 同一观点至少 3 名独立作者支持，才标记“多次出现”。
- 主要分歧两侧各至少 2 条独立样本。
- 原句与翻译分开保存，所有引语必须能回到作者、平台和永久链接。

## 图片优先级

1. 原文合格图片。
2. 同一 Story 历史快照图片。
3. 官方或其他核验来源图片。
4. 正文图表、产品界面和代码区域截图。
5. 社区原句局部截图。
6. 基于已核验事实生成的确定性信息卡。
7. 没有合格素材时明确无图，不生成无关 AI 图片。

`blocked` 图片不能同步；`warning` 必须人工确认；`allowed` 才能直接使用。图片元数据记录指纹、来源、作者、原始链接、适用平台、到期时间、视觉角色、对应段落和图注。

## 数据、任务与恢复

- `.workflow/newsdesk.db`：SQLite 主库，启用 WAL。
- `.workflow/media/`：草稿和 Story 图片。
- `.workflow/materials/`：确认可复用的素材。
- `.workflow/backups/`：迁移快照、恢复检查点和完整归档。
- `.workflow/state.json`：迁移后的只读回滚文件，不再长期双写。

采集、Story 图片补齐和素材包成稿通过持久任务表执行。任务有幂等键、进度、租约、重试和脱敏错误；进程中断后可以恢复。完整归档包含数据库一致性快照、媒体、素材、轻量状态备份与 SHA-256 manifest，不包含钥匙串中的 AppSecret 或 API Key。

测试和临时实例通过 `AI_NEWS_DESK_WORKFLOW_ROOT` 使用独立数据目录。AI 临时任务文件、终态任务/事件和便携归档都有保留上限；Windows 后台日志会轮换，计划任务在临时失败后最多重启三次。Windows 密钥使用当前用户 DPAPI，macOS 使用钥匙串。

## 发布门槛

- 所有事实都能回指证据，未支持事实阻断同步。
- 社区原句保留作者、平台、原文和永久链接。
- 有图片的来源优先提供至少 2 张相关视觉素材。
- 微信重复同步不重复创建草稿。
- 最终发布只能由用户在平台后台完成。
- 至少 5 次有效手动编辑后，写作偏好才开始影响后续生成；记忆可查看、关闭和删除，且永不修改事实评分。

## 编辑质量回归

`DraftDesk` 在落盘前执行确定性的分层质量门，阻止社区渠道标题化、评论语料误入新闻、原文副本混入热门评论、事实段落缺少证据、伪造社区共识和工作流术语泄漏。事实安全、来源归属和图片权利属于硬错误；内容覆盖与图片数量属于可修复警告。内容完整度依据段落登记的 ContentPackage 事实、未覆盖事实和“事件／机制／影响／限制”维度判断，不用固定字数冒充质量。纯内容警告可在同一草稿版本上执行一次证据受限的精确补丁，应用后重新运行全部硬门。它与模型审校分离：模型只提出局部补丁，确定性规则只依据可重复检查的数据和文本。

运行 `npm run eval:editorial` 可回归 22 条人工标注案例，覆盖新闻 8 条、社区 6 条、原文 3 条、写作 3 条和图片 2 条；新闻案例额外固定“短而完整应通过”和“长而重复仍警告”。内容策略页同步显示结果；提示词、路由、证据或图片规则导致任一案例不符合预期时，基线不会显示为通过。每次生成同时保留质量报告与候选草稿快照，因此硬阻断也可复现，不会只留下一个笼统失败通知。
