# 本轮平台交付与验收边界

三批工作保留 Claude #51–54 的产品入口、编辑状态所有权、队列、幂等控制和恢复设计。正式服务未更新；以下是实现与隔离验证，不能作为真实账号验收。

## 当前交付链路

写文章 → 顶部交付草稿 → 保存当前版本 → 沿用选择和本稿设置 → 自动连接/等待登录 → 逐平台上传与存稿/填入 → 保留结果 → 用户到平台核对并最终发布。平台设置、字段核对明细均默认折叠，不增加写作或交付的必填步骤。

## 隔离验证

- Node 22 下 `npm test`：1,453 / 1,453；`npm run eval:editorial`：22 / 22；隔离 `build -- --outDir .artifacts/verify/dist --emptyOutDir` 成功；指定隔离 dist 的 `test:e2e`：20 / 20。没有跳过或放宽测试。
- 回归覆盖微信留言权限不一致、小黑盒认领时的扩展版本、头条缺少草稿能力和不匹配回执、未知回执的版本保留、连续 10 次重试只存 1 次草稿、正文图片兼封面只上传 1 次、后台能力缓存与连接换代隔离。
- 浏览器验证常用平台一次交付、刷新不重发、字段明细默认折叠、1440 / 390 宽度无横向溢出；截图全部使用生成的本地隔离草稿和模拟回执。[桌面截图](design/writing-flow-2026-10-22/delivery-fields-1440.png)、[手机截图](design/writing-flow-2026-10-22/delivery-fields-390.png)。截图为查看明细后的状态，正常交付不必展开。
- 平台能力检查在后台缓存；连接改变后旧结果失效。慢检查不要求额外点击，也不据此把其他平台的交付结果隐藏。

## 已知限制及下一步

- **“平台内不用补改”尚未完成真实验收。** 本轮用户禁止向真实平台账号发送内容，因此没有发测试草稿。此前尝试只读查看头条，页面持续白屏，已关闭本轮创建的标签组；没有用看不到的字段编写并宣称成功的页面选择器。
- 公开同步桥接只提供 listPlatforms、checkAuth、uploadImage、syncArticle 等操作；未提供按草稿 ID 读回正文和设置的协议。当前版本的私有头条适配器不能仅凭公开支持列表审计。选择封面的请求会传递给助手，但是否实际应用必须通过版本匹配的真实账号验收。
- 公开百家号适配器的文章保存实现没有消费 article.cover，故不能承诺已解决百家号封面落地。需要能按草稿 ID 读取并补齐设置的适配器，或在确认安装版能力后做针对性改造；单纯增加成功提示无法解决。
- 小红书公开适配器也位于未取得的私有模块中，且图文内容形态不同。后续先确认用户实际常用图文形式、封面及图片组规则，再做自己的适配；本轮未引入虚假的能力标记。
- 真实验收应对每个平台固定同一篇合成稿，在不同登录状态、图片/封面、权限与计划配置下逐项核对，并记录“原生操作次数 / 工作台操作次数 / 平台内补改次数”。这些数字当前未知，不填估计值。最终发布继续由用户手动执行。
