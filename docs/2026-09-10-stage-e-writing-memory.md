# E1：可解释的个人表达偏好

已完成 E1 工程与隔离验收；与此前 A–D 一并交付 GitHub main，供 Windows 实机测试。真实稿件质量、公众号和手机验收仍独立保留，不能把隔离数据算作用户试用。

## 实际行为

- 只有明确确认、实际发生变化的人工编辑才计入新门槛；自动保存、旧版未标记确认的反馈、含 AI 修改的确认周期不解锁偏好。
- 至少五次有效人工确认修改；每条偏好还须由至少三篇不同确认稿支持。单次返工不会马上影响后续稿件。
- 每条依据保留稿件 ID、确认 ID、主题、修改摘要与前后至多 400 字的观察片段；原稿和完整版本仍独立保留。每种偏好保留最近二十条依据，计数与保留详情有区别。
- 推断段落长度时读取实际富文本；旧 paragraphs 数组未同步也不会漏掉导语和段落修改。
- 确认事件去重：相同确认重试不重复计数，已删除记忆不会因相同确认重放复活。未来新的真实确认仍可重新形成偏好。
- 使用本地 FTS5/BM25 检索当前选题，索引仅存在于本次内存数据库，中文使用双字片段；FTS 不可用时回退关键词匹配。无主题匹配时仅采用跨稿稳定的通用表达建议，最多三条。
- 只输出预定义的表达建议，不把历史稿件的数字、引语、原文或导入标签作为新稿事实/模型指令。数字、图片、社区引用的建议均明确服从本篇冻结素材及权利门槛。原文工作副本完全不应用个人表达偏好。
- 成稿和 Tab 续写共用检索；成稿 provenance 保存实际使用的偏好及依据，续写响应也带本次计划。正文资料面板可查看成稿时使用的偏好。关闭和删除影响未来请求，不擅自重写旧稿或删除审计历史。

## 使用入口

“内容策略 → 从修改中学习”：查看、关闭或删除单条偏好，展开全部保留依据；“预览当前选题会用哪些偏好”只做本地查询，不调用模型。全局开关关闭后全部停止应用。原文工作副本的预览明确说明保持原作者结构。

新安装或真实确认不足时显示等待样本，不预填任何虚构偏好。此次 E2E 的五份样本仅位于已清理的临时数据库，没有进入正式用户数据。

## 验证

Node 22.23.2 / npm 10.9.8，`npm ci` 成功；1045/1045 主测试、48/48 前端根目录补充、编辑黄金集 22/22、发现 72/72、抽取 12/12、事实完整性 40/40、类型检查与生产构建、6/6 浏览器流程全部通过。GitHub CI 在 PR 上另行执行，实际状态以 PR 检查为准。

新增反例覆盖：相同确认重放、删除后重放、旧自动保存记录不能解锁、不同稿件稳定性、富文本与段落数组不一致、未匹配主题、查询中引号/操作符、恶意导入标签不进入提示、关闭和删除、原文工作副本退出。原有事实和图片规则评测保持通过。

原创小样本比较：两种方法均 7/7，关键词匹配约 1.21 ms、FTS5/BM25 约 2.11 ms（单次本机观察，不是性能承诺）。当前没有证据证明语义检索能改善真实写作，未引入向量库、外部 API 或付费服务。保留 BM25 词频权重及可解释回退，不宣称它已经提升真实选题或编辑质量。

浏览器实际检查 1440/390px 的记忆依据、主题预览、单条暂停/启用、原文方向不应用、删除后刷新；未发生模型调用或外部平台写入。日志和图片位于 `.artifacts/phase-e/`，本地源代码检查点位于 `.artifacts/phase-e/baseline/`。
