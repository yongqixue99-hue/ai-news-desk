# AI 新闻台：日常编辑体验改进

日期：2026-09-05

后续已按用户反馈完成「重要发布不被埋没」与「原文图表随稿带入」，详见 [第二轮改进与实测](2026-09-05-release-and-materials.md)。

接续执行顺序与真实内容验收标准见 [后续规划](2026-09-05-next-roadmap.md)。

## 判断与范围

现有系统已具备采集、Story 聚合、冻结证据、图文成稿、人工编辑和公众号草稿交付能力。本轮审计基线为 628 项测试通过、构建通过。当前优先级是缩短从打开工作台到开始编辑的路径，并修复会中断工作的问题。

## 本轮交付

1. 今日页保留 3 条重点和 5 条次级候选，以报刊式版面区分重点、速览、继续编辑和观察中的事件。原标题、来源与证据阅读器继续保留。
2. 桌面首次打开显示带文字的导航，保留手动折叠偏好；手机保留底部五项导航。提供清晰的空态、加载态、错误恢复和键盘焦点。
3. 首页提供最近未完成草稿入口。服务端只返回必要的标题、状态和时间，沿用草稿目录规则，不传正文、图片或历史版本。
4. 来源诊断默认折叠；日常编辑动作与运行统计分区。可用来源图和发布权利状态继续分别展示。
5. 修复浏览器存储受限造成的白屏，以及后台任务打开错误草稿的问题；页面分包，降低首页加载量，分离编辑器依赖。

## 视觉规范

- 暖白纸面、墨色正文、朱红主操作。绿色和琥珀色仅表示状态。
- 中文界面使用系统字体，标题搭配系统宋体；取消首屏对远程 Google Fonts 的依赖。
- 主阅读列与约 280px 的工作侧栏；在平板和手机上自然合为单列。
- 首页仅使用实际来源图片。缺图时显示明确占位，不填充无关图片。
- 常用正文 14–16px，说明至少 12px；大数字启用等宽数字。交互保留可见焦点，尊重减少动态效果设置。

## 验收

必须通过 npm test、npm run eval:editorial、npm run build，以及隔离数据实例中的桌面/手机浏览器检查。额外核对：存储被禁用仍可导航，任务打开准确草稿，最近草稿排除历史旧稿与已发布稿，空态可继续操作，页面无横向溢出。

所有验证使用独立临时数据或只读页面快照；不以测试名义覆盖 .workflow。最终发布仍由用户在平台后台完成。

## 实施记录

- 已完成今日首页与全局导航的版面更新，新增 DraftDesk 的草稿摘要投影和只读接口 `/api/drafts/overview`。它沿用现有草稿目录规则，排除历史旧稿、已搁置和已发布稿，最多返回 3 条，保留进行中总数。
- 已复现并修复偏好存储被禁用时的白屏；后台任务根据 result.draftId 打开对应草稿，并处理打开失败。侧栏快捷键不再截获富文本子节点的 Ctrl+B；移动导航支持 Escape 关闭并恢复焦点。
- 今日刷新忽略过期响应；离开阅读器后停止讲解轮询。图片失败与具体 URL 绑定，来源图更新后可以重新显示。
- 构建主入口从 295.65 KB 降至 113.29 KB（压缩后文件、gzip 前，约减少 62%）；编辑器从单个 589.99 KB 包拆为 144.58 KB 的工作区与 445.31 KB 的编辑器依赖。没有提高大包警告阈值。
- 浏览器检查覆盖 1440px、1024px、390px 和 320px 宽度；确认无首页横向溢出，并检查空态、移动导航、指定草稿打开和存储受限场景。
- 最终验证：npm test 630/630，编辑质量黄金集 22/22，生产构建和端到端回归通过。真实公众号新建/更新与连续 12 篇试用仍是后续验收，不属于本轮已完成项。
