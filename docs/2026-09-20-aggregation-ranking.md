# 聚合资讯的两层排序（2026-09-20）

## 用户约定

单平台保留自己的组织方式；全部平台由工作台统一组织。不能把汇总排序后的结果简单过滤成单平台，也不能沿用另一平台的标题和摘要。

## 单平台

- AIHOT 新增匿名公开 v1 热点榜和精选接口。热点榜使用平台真实的 1–10 排名；精选沿用 API 返回顺序与平台推荐理由。平台评分标为编辑评分，不当作热度值。普通 RSS 动态仍单独可读。
- AlphaSignal、Ben’s Bites、AINews 保留订阅顺序、各自的标题与摘要；未接入的站内投票、个性化推荐或热榜不模拟。AIBase、AI工具集仍是待接入。
- 平台排序与工作台过滤分离，因此某条内容可以在平台榜单出现，而不在汇总精选出现。
- 各路线成功快照独立保留；RSS 成功不能抹掉失败的热点榜。空榜成功会清空旧榜，读取失败保留旧榜并提示。榜单快照超过 6 小时，不再用于汇总热度加分。
- AIHOT 精选优先采用公开 API 的完整顺序，精选 RSS 只在没有成功 API 快照时兜底，避免两种顺序交叉插入。

## 全部平台

默认“热点精选”，另有“最新动态”和“日报合集”。精选最多 30 个事件，不用普通动态填满。

确定性推荐规则：具体产品／成本／安全进展优先，其次有用实践；平台当前热点排名提供有界加分，精选提供有限加分，48 小时内按来源时间连续衰减。没有公共热度证据时显示“热度未知”。广告、传闻、常规维护、日报、未知或未来日期、超窗内容不进入精选；仍可从动态或所属平台查看。原始发布时间与平台事件进展时间分开，收录或重复抓取不能刷新原始发布时间。

重复链接、AIHOT 明确事件成员、同版本同类型的产品发布及高度近似标题可合并；相同模型名称本身不足以合并，不同版本、不同产品变体、发布与后续价格变化保持分开。使用官方事件页的 reports 成员，不合并 related 邻近事件。合并保留各条原文链接，同事件的热度只取一次，不累加转载次数。仍有保守规则不能识别的异名事件，后续可以通过漏报／误合并回放完善。

候选评分同时修正：聚合与社区角色不计作独立事实确认；同一出版域名的多条入口不重复增加跨源分。没有改写旧稿、素材或事实包。

## 公开数据合同

- https://aihot.news/agent
- https://aihot.news/openapi-v1.json
- https://aihot.news/api/v1/hot-topics
- https://aihot.news/api/v1/items?mode=selected&window=7d&limit=100
- 事件成员只从接口返回的事件链接提取 publicId，调用 `/api/v1/stories/{publicId}`；最多 10 个，3 路并发，复用 SourceDesk 缓存、条件请求与失败隔离。

不读取私有接口，不需要新增密钥；不改变最终发布流程。每个平台每个频道最多保留 100 条摘要，每条最多 1600 字符。

## 验证

1074 项主测试、编辑黄金集 22/22、发现回放 72/72、TypeScript/Vite 构建通过。浏览器测试覆盖汇总排除推广、单平台保留推广榜首、跨平台文案隔离、筛选、选题保存、重新加载、失败状态与 1440/390 像素布局。

真实回放补充了“Anthropic 或发布新模型”降级、Qwen3.8 LiveTranslate 中英文合并、紧凑版本名区分，以及 AIHOT 安全事件多报道归并；平台事件聚合代表平台的分类，不构成工作台的事实核验。
