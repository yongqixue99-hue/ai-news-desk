# 2026-10-02 交付调度、续接与改稿记录

用户已授权继续优化，并明确真实平台验收可以后置。本轮完成本地实现和隔离测试；没有发送到真实外部账号，没有调用最终发布或群发接口。产品仍以公众号草稿箱为主，小黑盒为兼容填入渠道，头条为编辑入口。

## 独立调度与处理时限

统一交付模块只在分派任务时持有全局调度锁，执行期间使用各平台自己的锁。一个平台慢，不影响另一个平台登录后继续。连接检测默认 30 秒，实际交付默认 10 分钟；这些是交付时限，区别于一般后台任务的 15 分钟无进展 / 45 分钟总时限。

检测超时且尚未提交的任务可重试；已经进入交付的超时任务标为结果未知，不自动重发。取消信号传入各渠道，微信 HTTP 请求也接入该信号。已经发出的浏览器操作只能等待其原有有界执行结束；执行器退出前保留平台占位。迟到回执不能直接复活已超时的任务，后续只读读取已有渠道回执才能恢复状态。超时结果遇到临时本地存储错误时会再次尝试保存。

## 小黑盒文章逐图与封面续接

浏览器助手 v0.1.28；最低兼容版本仍为 v0.1.24。使用新增续接能力需要重载已安装的扩展一次，旧版连接不会因本轮功能被强制拦截。

- 每张已上传图片记录稿件 ID、内容哈希、平台草稿 URL、最新正文签名、对应的原生图片 URL 和剩余图片标记。失败后先读取实际页面，匹配才跳过已有图片并补上传剩余部分。
- 在剩余图片全部加入之后重新填写所有图注，再读取检查，避免平台重绘清掉前面的图注。找不到已记录图片时不会继续上传。
- 封面绑定本地封面数据哈希与实际平台封面 URL；核对匹配后不再重复上传。
- 仅有明确的原生文章草稿 URL 时保存可靠检查点。平台中已编辑的正文、图片或封面会要求先核对，不直接覆盖；本地内容改动只会替换仍与原检查点一致的远端稿。
- 图文图集仍沿用现有整体上传流程，本轮没有宣称其支持逐图续接。扩展检查点不包含文章全文、图片字节或凭据。

## 平台独立标题与封面

“交付草稿 → 多平台”增加默认折叠的“平台标题与封面”。百家号和知乎支持为本篇文章保存独立标题和封面；留空时沿用原稿标题、正文第一张图片。不增加单独保存步骤，随草稿自动保存，并纳入本地恢复缓存和历史版本恢复。

原标题和正文不被覆盖。交付签名只增加对应平台的配置，修改另一个平台不会令本平台的回执失效。平台标题仍核对标题长度和冻结事实；来源变更确认保持绑定原编辑稿，不因替代标题被错误作废。公众号继续使用现有作者、摘要与封面设置；外部同步助手没有已验证的摘要字段，未增加无效摘要配置。

封面可以来自正文之外的受管理图片，但它必须参与平台资格检查、本地路径和 SHA-256 校验；全部文件校验完成后才开始上传。正文与封面共用同一张图时只上传一次。标题、封面或账号在途中改变时停止后续投递。百家号/知乎仍是“助手报告存稿”，没有声称独立核验了远端内容。

## 实际改稿与返工记录

“版本 → 改稿记录与返工原因”默认折叠，展开才读取统计。显示捕获基线与当前保存稿之间的标题变化、按顺序完整保留的正文块、新增/改写/删除块、实际正文或图集中图片的增减和图注变化；未插入的素材库图片不计入。图注读取实际编辑后的正文，而非只读取旧素材标签。

只读接口：`GET /api/drafts/:draftId/rework`。原有可选返工记录继续使用版本绑定、幂等请求 ID 和用户自填分钟数。没有测量时保留未知，不换算停留时长，不把改动量当作质量或事实错误评分，也不自动修改事实分或表达记忆。

`GET /api/workflow/performance?days=30` 和本地报告增加实际返工原因的记录次数、独立稿件数、自填耗时和未测量记录数。数据库按事件类型与统计窗口先过滤后截取，采集日志不能挤掉编辑记录。最多读取 10,000 条，返回已保留记录总数和是否截断；只统计仍保留的真实记录，不补造旧历史。

表达学习原有的五次有效人工确认、三篇独立稿件门槛和 AI 协助排除规则保持不变。当前记录能力为后续改善初稿提供依据，本轮没有宣称已经量化证明初稿质量提升。
