# 信息源覆盖与紧凑选题表

## 本轮目的

把七层发现方法用于检查来源缺口，并把已有 Story 与聚合热点合成一张可操作的选题表。七层不是七个首页面板，也不是每件新闻必须满足的七项条件。发现用途和事实可信度分开。

## 来源安排

| 用途 | 已有与本轮实现 | 使用边界 |
| --- | --- | --- |
| 消息源与聚合 | 官方新闻、Reuters、TechCrunch、The Verge 等已有路线；AIHOT 等聚合发现 | 付费墙、搜索摘要不能补成全文；转载不是独立证实 |
| 开源项目 | 复用 GitHub 项目发现 | 当前适配器不是承诺完整复刻 GitHub Trending；README 不等于实际试用 |
| 技术讨论 | 复用 HN、V2EX | 链接到外部原文时仍按 source-first 核验，讨论量不是共识 |
| 新产品 | 新增 Product Hunt 公开 Atom，加入默认采集和新安装的来源预设 | 没有投票与榜单数据，不模拟热榜；明确 AI 工作任务的产品可作待试用线索 |
| 用户案例 | 尚未自动接入 Reddit | 本轮公开 RSS 实测失败；保留原帖手动导入途径，收入、效果为待核实的个人叙述 |
| 中文趋势 | 36氪站点检索、量子位、机器之心、需配置的知乎 | 未接入微博／百度热榜／掘金；36氪官方 RSS 本轮返回 HTML，不能标记为已接通 |
| 内容需求 | 手动收录资料，建议每周观察 | 公众号、小红书、付费平台暂无自动需求统计；阅读、销量不能直接证明需求 |

2026-09-20 实网探测：Product Hunt HTTP 200 / Atom，共解析 50 条，保留发布时间。当前 48 小时 AI 过滤后 1 条候选，42 条超过窗口、7 条未达评分或主题门槛；这些是本次读取结果，不是固定条目数或覆盖率。Reddit 获取失败，36氪 `feed-newsflash` 返回非 RSS HTML。

参考官方入口：[Product Hunt API](https://www.producthunt.com/v2/docs)、[Reddit Data API](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki)、[36氪 RSS](https://www.36kr.com/rss-center)。本轮只接入经过实测的免费公开订阅，没有新增 API 付费或登录凭据需求。

## 汇总与排序

`TopicRadar` 是 Today 的只读投影，通过 StoryDesk 输出；不新增写作事实、修改评分或触发模型调用。聚合原生顺序保持不变。

- 首页汇总最多 8 条，使用明确变化／具体实践、时效和已有平台热点信号。缺额保留，不以普通动态凑数。
- Story 使用原有新闻 48 小时、官方发布补看 7 天、实践 30 天窗口。聚合只取原有 48 小时精选规则。
- 在汇总投影中，重要变化 40、实践／用途 20，48 小时内时效最多 20；近期聚合热榜信号最多 20，Story 可进入成稿的材料状态加 4，既有个人偏好调整限制在 ±4 内。数值只用于展示顺序，不写回事实或推荐评分。
- 只用同一原文／保守事件匹配合并，原始链接、平台链接仍可展开查看。不把同名模型不同动作合并，不以复制次数加分。
- 已忽略、已成稿、已发布的 Story 不会通过相同聚合事件再次进入首页。
- 产品自述仅提示潜在用途，标记待试用，不生成“好用”“节省多少时间”等结论。
- 无可靠热度显示“热度未知”；待核对线索与可进入成稿分开。最终仍要走 ContentPackage、原有质量与权利检查。

## 界面方案与落地

1. **今日**：紧凑选题行展示标题、简短推荐理由、材料状态和下一步；摘要与来源折叠。联网补搜、筛选与排序、官方技术资料按需展开。原有单平台栏目、阅读器、待选题与草稿保留。
2. **新闻源**：默认先看到管理列表；七层覆盖在一个折叠区内，分别显示加入默认采集、正常、未检查及需关注数量。用途筛选不会改变可信度角色。X 接入与来源预设收进另一个折叠区。
3. **更新**：后台新增结果仍提示“显示更新”，不在阅读时重排列表。浏览和过滤不启动采集或 AI。

来源配置加入默认采集不等于正在运行：使用现有自动化计划，没有另建全天候监控或早报推送。旧来源的启停、用户自建组合、稿件、素材和凭据保持原有存储。

## 后续优先级

- 用实际关注热点建立漏报清单，度量发现延迟、首屏选题质量与重复合并率，再决定增加平台。
- 在具备正常访问条件后验证 Reddit 案例采集；不通过登录绕过或伪造采集成功解决缺口。
- 将手动收录的内容需求整理为每周观察记录，区分问题、作者自述、指标快照和待核实判断。
- 若需要主动早报，再基于现有自动化确定时间、报告内容和通知方式；本轮没有擅自启用新通知。

## 验收

本地 1102 项测试、编辑质量黄金集 22/22、TypeScript 和生产构建通过。八组浏览器场景通过，包含新增汇总去重、材料状态、来源用途过滤，以及既有原生平台排序、阅读器、交付和编辑流程。桌面与 390px 手机截图已人工检查。真实数据复核额外覆盖了 Qwen 同一次发布的旧重复 Story：仅合并展示，证据存储和选题身份不重写。

Mac 服务更新前后，21 篇草稿及素材、发布回执的校验值一致。Windows 的来源可达性仍取决于本机网络，未把 Mac 探测结果当成 Windows 实机采集成功。
