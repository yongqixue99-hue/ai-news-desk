# AI 新闻台核心工作流审查

审查日期：2026-08-11  
范围：采集工作台 → 草稿编辑与版本 → 发布准备 → 新闻源 → 定时任务 → 运行记录 → 手机端草稿与发布。  
目标：让用户每天无需临时提供链接，就能可靠地完成采集、筛选、成稿、配图、修改和手动发布。

## 步骤与整体健康度

1. **采集工作台 — 需改进**  
   结构清楚，来源、时间窗和图片策略集中在一个入口；但顶部停在“筛选”，右侧所有阶段又显示完成，且零候选仍以绿色成功呈现。空结果没有解释来源故障、过滤过严还是确实无新闻。
2. **草稿编辑 — 良好**  
   连续编辑、对照预览、原图和自动保存已形成可用主流程。工具栏依赖图标和原生 `title`，触摸设备与键盘用户不容易发现含义。
3. **版本历史 — 良好**  
   当前内容、自动保存、手动版本和恢复动作清楚。窄桌面打开抽屉时，预览被遮成一条不可读的窄栏。
4. **发布准备 — 需改进**  
   平台、社区、话题和“不会自动发布”表达清楚；但三项事实待确认与禁用的主按钮没有形成直接因果说明，用户不知道下一步该处理什么。未来平台的禁用卡片目前占据较多首屏空间。
5. **新闻源管理 — 需改进**  
   “发现源 / 事实源”区分是正确方向。列表缺少分组、搜索、健康状态、上次成功采集和错误信息；“启用”和“默认采集”两列也容易混淆。
6. **定时任务 — 需改进**  
   基础配置简洁，但没有显示精确下次运行时间、最近一次结果、Mac 睡眠或关机后的补跑规则，也没有测试运行或完成通知。
7. **运行记录 — 风险较高**  
   记录可追溯，但短时间内出现六次零条目运行，系统没有阻止重复启动、取消或合并任务。零结果仍显示绿色对勾，会掩盖采集异常。
8. **手机端草稿 — 风险较高**  
   编辑器与预览默认上下同时出现，首屏很快进入预览；工具栏换行，页面底部同时存在草稿工具栏和全局导航，消耗较多可编辑高度。手机端应默认“仅编辑”。
9. **手机端发布 — 基本可用**  
   发布面板能占据主内容区域，但缺少标准抽屉的焦点管理、遮罩、滑动关闭和返回焦点行为。

## 最高优先级问题

### P1 — 运行可靠性与空结果诊断

- 同一采集任务需要幂等锁、队列状态、取消与重试。
- “0 条”应是警告状态，并展示每个来源的抓取结果、过滤原因和建议动作。
- 顶部步骤、右侧阶段和运行记录必须由同一状态模型驱动。

### P1 — 发布阻塞原因

- 主按钮旁直接显示阻塞项，例如“先启动专用 Chrome”“还有 3 项事实待确认”。
- 每个待确认事实应能跳回对应段落或来源证据。
- 图片版权/转载状态应进入发布检查，而不只保留在数据字段里。

### P1 — 自动化韧性

- 明确 Mac 睡眠、关机、服务退出后的补跑策略。
- 显示“下次运行：8 月 11 日 22:30（Asia/Shanghai）”和最近一次结果。
- 增加一次性测试心跳与完成/失败通知。

### P1 — 手机端默认模式

- 小于 720px 默认“仅编辑”，预览通过顶部切换进入。
- 草稿工具栏与全局导航避免同时占两层固定底栏。

## 第二优先级机会

- 保存“来源组合预设”，例如“模型厂商”“主流媒体”“开发者热榜”。
- 对新闻候选显示重复报道聚类、首发来源和多源交叉核验。
- 建立个人写作风格档案、禁用套话和发布前“AI 味”检查。
- 将正文中的关键事实与来源逐条关联，而不是只在文章级展示来源列表。
- 增加草稿导出/导入和本地状态备份，防止机器迁移或状态文件损坏。
- 为小黑盒、公众号、小红书建立独立的平台适配层与字符/图片约束，而不是在一个面板内逐步堆条件。

## 代码层面容易被忽略的风险

- `createCollectionRun()` 每次调用都会新建并异步执行任务，没有运行锁或幂等键；当前 UI 虽会在本页禁用按钮，但多标签页、重复请求或服务重试仍能创建并行任务。
- 定时器只在“当前分钟恰好等于设置时间”时触发。Mac 在该分钟休眠、关机或服务重启后不会补跑；自动成稿的等待循环也只存在于当前进程，重启后不会恢复。
- 页面和图片读取虽然拒绝了 `localhost`、回环地址与 `.local`，但还没有解析并阻止私网 IP、IPv6 私网和逐跳重定向；未来放到服务器并允许自定义来源前，需要完整 SSRF 防护与出站网络策略。
- `.workflow/state.json` 采用临时文件后原子重命名，能降低半写损坏风险，但没有滚动备份、校验或一键导入/恢复。
- 发布自动化依赖小黑盒页面控件结构；需要“试填检查”、选择器健康测试、失败截图和版本化平台适配器，避免网站改版后静默填错。

## 可见的无障碍风险

- 多个纯图标按钮仅依赖悬停标题；移动端无法获得同等提示。
- 部分辅助文字约 8–9px，缩放和低视力场景可读性不足。
- 现有自制抽屉没有从截图确认焦点锁定、返回焦点和背景不可交互。
- 禁用主按钮的低对比粉色仍像主要操作，但缺少可感知的原因说明。

截图只能确认视觉和部分 DOM 语义，不能据此声称完整 WCAG 合规；键盘顺序、屏幕阅读器朗读、200% 缩放与减少动态效果仍需实际测试。

## 本轮已落地

- Appica/Tailwind 试点已按用户反馈撤回，恢复原来的草稿布局、右侧面板和通知样式；只保留以手写 CSS 实现的轻量按压、焦点和减少动态效果反馈。
- 小于 720px 首次打开草稿时默认“仅编辑”。
- 发布面板新增明确阻塞原因，并把图片转载权限纳入发布检查。
- 采集结果为空时改为黄色告警，提供“检查新闻源／重新采集”；运行记录中的零结果也不再显示绿色成功。
- 采集增加进程级取消、状态持久化、并行任务锁和按原来源/时间窗重试；服务重启后会把中断任务明确标为失败并给出重试入口。
- 心跳从“只匹配一分钟”改为当天过点补跑一次；下次运行、最近结果和 Mac 唤醒策略在设置页可见。
- 新闻源列表增加搜索和最近健康状态；每次运行保留逐来源原始条目、候选数与诊断。
- 远程页面与图片读取增加协议、凭据、DNS、私网/保留地址、逐跳重定向和响应体大小限制。
- `.workflow/state.json` 写入前保存滚动备份；当前文件损坏时会保留损坏副本并尝试恢复备份。
- 小黑盒填入出现控件缺失或操作异常时保存失败现场截图，并把路径写入填入结果。

## 回归结果与代价

- TypeScript 与生产构建通过；服务端测试 14/14 通过。
- Appica 与 Tailwind 依赖已完全移除。当前 gzip：主 CSS 约 12.00 kB、主 JS 约 74.27 kB、草稿懒加载块约 161.85 kB。
- 桌面草稿/发布面板、工作台空结果、来源、定时、运行记录以及 390×844 手机草稿/发布面板均已在本地生产服务中回归；浏览器控制台无 error 或 warning。
- 草稿懒加载块仍略高于 Vite 的 500 kB 原始体积提示线；它不进入首屏主包，后续可以按编辑器扩展继续拆分。
