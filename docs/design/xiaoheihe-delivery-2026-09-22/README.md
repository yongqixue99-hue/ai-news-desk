# 小黑盒交付减法

本轮优先处理小黑盒，保留红白视觉与现有草稿架构。

- 交付面板默认小黑盒。主操作“送到小黑盒”完成保存、连接 Chrome、预检、填入、回读；默认设置收起。
- 盒友杂谈独占一个社区。其他社区自动补 Steam / 数码硬件，新稿轮换，同稿重试保持不变。
- 每篇固定 AI、盒友杂谈、盒友日常、Steam 游戏，可补一个话题。
- 所有人可见。创作计划默认不参与；开启时选择常规计划或热点计划。常规计划跟随实际编辑器：文章对应“文章计划”，图文对应“图文计划”。
- 创作计划封面独立选择或上传，不插入正文；检查实际文件、SHA-256、授权平台、900×480 最低尺寸及 10 MB 上限。通过平台自己的上传与裁切界面填写封面。
- 不新增声明类表单。最终发布仍由用户在小黑盒点击。
- 对照模式两侧各占一半，同宽纸张、同一顶部和标题区域。工具栏换行时同步预览栏高度。

## 可靠性

发布设置参与草稿恢复、版本快照和交付修订哈希。改变计划或封面会将原交付标为待同步，不影响公众号回执。

回执必须包含可见范围、创作计划、封面核验。缺少结果或上传失败不能显示“已填好”。长时间上传不再在 30 秒后重复领取同一任务；其他已打开的小黑盒草稿不会被导航覆盖。

## 实测依据

2026-09-22 在当前登录的小黑盒账号，实查文章/图文编辑器、计划标签、封面选择与裁切弹窗。社区实际名称为 CodeX / Steam / 数码硬件，话题忽略大小写和空格进行精确匹配。

检查：1133 项测试通过、编辑黄金集 22/22、生产构建通过。隔离工作台验证保存及回执；1280 像素视口下对照画布两侧均为 456.5 × 599 像素，顶部均为 310 像素。

真实平台验证：CodeX + Steam、固定四话题、文章计划均填入成功。随后以盒友杂谈单社区 + 热点计划 + 独立封面完成端到端填入，标题、正文、配图、分区、话题、可见范围、创作计划、内容封面八项全部通过回读。验证稿没有正文图片，正文图片上传仍由原有回归测试覆盖；未点击最终发布。

实测修复两个问题：平台封面上传完成仍保留隐藏占位节点，现检查真正显示且加载成功的图片；助手重载后旧连接页停止领取任务，避免失效脚本抢到任务并误报失败。上传封面的使用权可在封面下方直接确认，不再跳转图片面板。
