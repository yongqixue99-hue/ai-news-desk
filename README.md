# AI 新闻台

一个运行在 Windows 或 macOS 本地、面向个人公众号创作者的 AI 科技编辑工作台。系统自动读源并把跨平台信号聚合为 Story，在“今日”页准备 3 条必看和 5 条次级候选；用户选题后先冻结事实、社区原句和图片素材包，再生成可编辑图文草稿，最后同步到微信公众号草稿箱。最终发布始终由用户在平台后台完成。

## 已实现的工作流

1. 新闻源以 OpenAI、BBC、Reuters 等母站官网展示；官网入口与后台 RSS／新闻索引接口分开保存。
2. “综合 / AI / 科技 / 游戏 / 电竞 / 政治 / 商业 / 科学”频道会把每个母站路由到对应子栏目；游戏与电竞另预置 IGN 和 Dot Esports。
3. 手动采集支持起止日期和逗号分隔的关键词；Horizon 先按日期扩展抓取窗口，再在本地做精确日期与关键词过滤。
4. 本地按所选频道、时效、后果、证据和传闻风险评分；动态新闻检索会随频道、日期和关键词变化。
5. “今日”页前五个 Story 异步补齐原图或定向截图；其他来源只在用户生成素材包时读取，避免全量渲染网页。
6. 采集完成前自动为候选生成中文标题与一句话摘要，并标明“已读原文／据来源摘要／仅据标题”；原标题始终保留，翻译失败不会阻断采集，可单独补全。
7. 首页每个 Story 都可打开统一的双栏阅读器：左侧核对来源、证据、趋势与原图，右侧先读一段像编辑给同事讲新闻的“编辑速读”，只在材料确实需要时补充具体信息、编辑备注和缺口，不再强迫每条新闻填写“实际影响／影响对象／来源贡献”等报告式栏目。事实层与展示层分开保存；历史 v1 讲解首次打开时会按需升级为 v2，不会全量重跑旧数据。来源被拦截或只有标题时会明确标记证据边界。
8. “新闻工作台”只显示媒体、研究与官方来源，固定展示 1 条“今日推荐”和 4 条次级推荐；超过 48 小时且未进入编辑流程的新闻自动退出首页，运行记录不删除。
9. “社区广场”是独立一级入口，不显示日期或采集按钮；后台把 Hacker News、GitHub、V2EX、知乎与 Last30days 信号按讨论主题聚合，淘汰过期内容，并结合各平台自身的互动增速、时效、内容价值和历史偏好推荐。
10. 英文社区热点进入广场后自动拆成“发生了什么”和“社区怎么说”，原标题与可追溯社区原句始终保留；卡片优先展示关联原文图片，原图不足时可渲染原页面截图兜底，并可把社区观点素材包送入私人草稿箱。
11. 用户勾选普通候选后，默认由 Codex 使用 ChatGPT 登录状态逐篇核验、成稿，不需要 OpenAI API Key；也可在“AI 设置”中切换到千问、DeepSeek、OpenAI API 或自定义兼容接口。
12. 成稿前先生成 ContentPackage，并在 `Brief / Synthesis / Community / Playbook / Curate / Watch / Skip` 中路由稿型；写稿只能使用包内证据，版权或事实阻断不能通过切换稿型绕过。
13. 草稿进入连续富文本编辑器，可任意拆分、合并和改写段落，也能在当前光标插入来源图、本地图片或图片网址。
14. 编辑停止约 1 秒后自动保存；手动保存会创建独立版本，右侧“版本”面板可随时恢复，恢复前也会自动备份当前内容。
15. 常用 Chrome 填入助手会在真实填入前检查扩展版本、编辑器、事实证据、图片权限、分区和话题；只填入，不点击发布。
16. 微信公众号适配器会检查标题、作者、摘要、事实证据、正文图片和微信平台授权；首次同步新建草稿，后续原位更新同一 `media_id`，内容未变时不重复上传。发布后需要用户回到工作台明确确认，系统才学习编辑差异并沉淀合格图片。

## 成熟版架构（v12）

复杂行为集中在七个稳定边界：`SourceDesk` 统一采集适配器，`StoryDesk` 聚合跨来源事件，`EditorialDesk` 做稿型与阻断判断，`PackageDesk` 冻结事实／社区／视觉证据，`DraftDesk` 管理成稿和版本，`DeliveryDesk` 负责幂等平台交付，`LearningDesk` 记录透明且可删除的编辑偏好。页面和路由只调用这些公开接口，不直接拼接来源、证据或发布规则。

- `Signal` 保存原始新闻、公告、帖子或评论；`Story` 表示聚合后的真实事件。
- `EvidenceClaim` 和 `DiscussionSample` 分别保存事实证据与可回链的社区样本。
- `ContentPackage` 是写稿的强制证据边界；模型不能凭记忆补充包外事实。
- `AssetCandidate` 保存图片来源、指纹、版权状态、平台范围、视觉角色和段落位置。
- `FeedbackEvent` 保存浏览、忽略、入稿、修改、同步与确认发布行为，不用一个黑箱偏好分数替代历史。
- SQLite 启用 WAL，并用可恢复任务表管理采集、素材补齐、素材包成稿和微信同步；前端通过精简查询与 SSE 获取进度。

## 内容策略与自动读源

- “内容策略”页保存用户掌控的长期定位、读者、主题、表达偏好和红线；后台任务只有读取权，不能覆盖。
- 近期编辑记忆只汇总最近 30 天用户明确标记的“感兴趣／不感兴趣／已发布”记录，作为软排序信号，不修改事实评分或长期档案。
- 当前简报硬性限制在最近 48 小时，同一新闻由头只占一个位置；重复报道并入佐证来源。未处理旧闻退出首页，已勾选、感兴趣、成稿或发布的旧条目沉到下方但不会丢失。
- 策略建议只根据真实反馈和来源健康记录生成。来源升降级与主题新增必须由用户“采纳”后才应用，“忽略”决定也会持久保存。
- 每日自动读源复用现有采集器，只访问同时“启用并选入”的 RSS、Google News、Hacker News、知乎 CLI 或 Last30days 来源；支持设定每日时间和手动“立即读取”，结果只进入候选池，不自动写稿或发布。

这一层借鉴了 MIT 许可项目 [ContentOS](https://github.com/star23/content-os) 的长期／近期档案分层、48 小时窗口、事件去重和建议审批思路；数据模型、采集、证据、版权和页面实现均在本项目内独立完成。

## 可信工作流（当前状态 v12）

- 截图或链接不会再直接黑箱成稿：先生成 Evidence Review，用户可恢复误删正文、排除导航杂讯、选择真实裁图，再确认成稿。
- 关键事实按“全文支持／仅摘要／多源确认／推断／未核验”逐条记录；弱证据和未解决事实会阻止填入。
- 文章分析、优化、追问与成稿都保存脱敏的 Provider、模型、Skill 快照、耗时、错误分类和重放 ID；不存在静默切模型。
- 图片素材保存授权状态、允许平台、来源页、证据、到期日、实体标签和 SHA-256 指纹；重复图片会被拒绝，待确认或过期授权不能发布。
- 发布前检查会生成结构化回执。只有标题、正文、图片、图注、分区和话题都通过，才显示“已填入”；最终发布仍必须手动完成。
- 草稿有待编辑、待核验、待配图、可填入、已填入、已发布、已搁置等明确生命周期。
- 新闻源支持频道／用途／健康筛选、批量维护、单源测试、连续失败诊断和可复用来源组合。
- 自动化页可导出完整 `.tar.gz` 归档，内含一致性 SQLite 快照、草稿图片、素材库、轻量状态备份和逐文件 SHA-256 清单；操作系统安全存储中的密钥始终排除。轻量 JSON 仍可单独导出和恢复。
- 候选可明确标记“感兴趣／不感兴趣／恢复”。个性化只改变“综合推荐”的次序，并单独显示加减分与原因；它不会改写新闻价值、证据、时效或传播信号，也可随时关闭或清空。
- 需要追溯的采集、成稿和发布连接结果进入通知中心；通知只在点击铃铛后展开，不使用悬浮弹窗干扰编辑。
- 确认真实发布后，可逐张把本次确实使用且授权合格的图片存入素材库；旧回执、未使用图片、目录外文件、重复指纹和版权不合格素材都会被阻止。

## AI 设置、Skill 与素材库

- AI 厂商按纵向列表管理，同一时间只启用一个成稿引擎。第三方 API Key 在 macOS 使用钥匙串，在 Windows 使用当前用户的 DPAPI 加密，不会写入 `.workflow/state.json`，也不会由初始化接口返回前端。
- 已预置 `news-desk`、`agent-reach`、`lieflat-less-ai-tone` 和 `ra-人话`。取材核验 Skill 只进入成稿／分析；默认用 lieflat 白名单做最小审校，`ra-人话` 只在明确评论稿或用户选择“加强人话表达”时叠加。Skill 可逐个启停，也可从工作区、`~/.codex/skills` 或 `~/.agents/skills` 导入其他 `SKILL.md`。
- 导入 Skill 只读取规则文本，不执行 Skill 目录中的脚本。每次生成会把实际使用的 Provider 和 Skill ID 写入运行快照。
- 图片素材库用于存放已确认可使用的官方图、人物照或品牌素材，可分别记录“小黑盒”和“微信公众号”的授权范围。草稿图片面板会复制素材到当前草稿，再插入光标位置；素材库原件删除后，已经插入草稿的副本不受影响。
- 同一个运行的“生成”请求有原子锁，重复点击会复用进行中的任务；已有草稿的候选不会被无意重复生成。
- AI 设置页把成稿、文章分析、文章优化拆成三个明确插槽，并为每个厂商提供安全的“测试连接”；测试结果只展示模型、耗时和脱敏后的可操作错误，不回显 API Key 或上游响应正文。

## 社区内容与 Last30days

- 侧栏“社区广场”与“新闻工作台”完全分开展示。用户进入广场就能看推荐，不需要再选来源、日期或点击采集；后台仍复用同一套定时读取、证据保存和来源健康机制。
- 社区广场默认只保留最近 7 天仍有效的讨论，同一讨论在多次运行中只显示一次；“不感兴趣”的条目立即退出，已感兴趣或已入稿的旧条目不会被误删。
- 卡片把事件事实与社区观点分开：前者回答“发生了什么”，后者提炼反复出现的经验、关注点和有证据的分歧；同时保留作者与社区原句，避免把评论数误写成“观点集中”。
- 同一讨论的多次采集会合并成一条主题，并保留历史快照、最新互动和图片；推荐理由显示真实新增积分／评论及时间窗口，而不是只看累计热度。
- 广场显示社区来源健康状态，并把匹配到的官方／新闻来源作为核验材料附在热点下方；新闻与社区仍独立浏览，但入稿时汇合成同一个来源包。
- `Last30days 社区趋势` 是默认提供但不默认勾选的选题源。勾选后按工作台频道或关键词扫描最近 30 天的 Reddit、Hacker News、X、YouTube、GitHub 等社区信号，并把趋势原因、社区原句和直接证据链接带回候选池。
- 不把不同平台的点赞、评论和播放量直接相加；Last30days 的动量只用于解释“为什么最近值得看”，事实评分仍要求回到来源核验。
- 首次使用时，在 Codex 对话中说“使用 last30days，先完成初始化”，并明确选择是否授权读取浏览器 Cookie。后台采集不会替你运行首次向导、安装工具或越过 Cookie 授权；来源页的“测试”会显示当前状态。
- “导入私有原文素材”不调用模型，仅用于个人草稿整理，不等于取得转载授权；“忠实翻译素材”逐块保持顺序、数字、专名与限定条件；默认的“社区观点素材包”提炼关注点、真实经验、分歧和待核验说法，但不能虚构事实或把社区观点写成已验证结论。
- 图片依次复用讨论历史快照、关联原文和匹配新闻来源中的合格图片；若仍不足且图片策略为“允许截图”，服务会打开来源页面，优先截取有信息量的正文图片，最后才用正文可视区域截图兜底，并在素材证据中标明截图来源。
- 三种模式都只生成私人编辑工作副本，保留原链接并标记转载、翻译和图片权利待确认。进入草稿箱不等于获得公开转载许可，也不会自动发布。

## 轻量交互与运行可靠性

- 保留原来的草稿布局和右侧资料／图片／版本／发布面板，不再加载 Appica 或 Tailwind 运行时。
- 按钮、侧栏图标、工具栏和来源选项有统一的按下位移、缩放、内阴影与焦点反馈，并尊重系统的“减少动态效果”设置。
- 手机端首次进入草稿默认“仅编辑”，避免编辑器与预览上下挤在同一首屏。
- 发布检查会明确显示 Chrome 未启动、事实待确认和图片转载权限待确认。
- 同一时间只允许一次采集；运行中的任务可取消，失败、取消或空结果可按原配置重试。
- 定时心跳错过设定分钟后会在电脑当天恢复运行时补跑一次；来源页会显示各来源最近一次原始条目、候选数和错误。
- 自定义远程地址会阻止本机、私网、保留 IP 和不安全重定向；数据库迁移、恢复和平台同步前会创建额外检查点。
- 小黑盒填入任一步骤失败时会把当时页面截图保存在 `.workflow/logs/`，方便定位网站改版后的控件变化。

## 连续编辑与排版

- 正文不是固定段落表单：支持正文、二/三级标题、粗体、斜体、引用、列表和链接。
- 图片可以从右侧来源图库插入，也可以选择文件、粘贴截图、拖放文件或输入图片 URL；本地文件保存在对应草稿的 `.workflow/media/` 目录。
- “排版预览”提供新闻简洁、黑白杂志和科技蓝三套轻量主题。
- “复制排版”会把主题样式内联到 HTML，并尽量把本地图片转成可粘贴的数据；“复制纯文本”用于不接受富文本的平台。
- 旧草稿首次打开时自动转换成连续文档，不会丢失原有段落、观点或来源图。
- 自动保存会持续落盘，并把五分钟内的连续修改合并成一个历史快照；每篇草稿最多保留 30 个版本，避免长期写作无限占用空间。

## 去 AI 味与安全改稿

- 系统不追逐某个 AI 检测器分数。默认按 lieflat 的明确白名单检查翻案壳、密集列举、相邻同构句、揭晓式破折号、提示词冒号、名词化和过长前置结构，再叠加聊天残留、宣传词堆叠、无来源权威等新闻编辑规则。
- “首先／其次”、正常提问、被动句、句中并列、引用原话和少于三项的真实步骤不会因为单独出现就被判成 AI 味；命中 lieflat 也只进入局部建议，不会自动触发整篇重写。
- 候选速读也执行同一套边界检查，并额外记录 `ra-人话` 中高频的二元翻案、伪洞察提示词、证据口吻套壳和机械日期换算。质量标记只用于返工和评测，不能改变事实或被当作证据。
- 已生成的编辑速读可由用户点击“换种说法”按需重写；重复点击复用同一持久任务，不会默认给每条候选多跑一次模型。
- 原稿已经具体、准确、顺畅时，优化 Agent 会返回“保留原稿”，不为了显示工作量强行重写。
- 需要改动时只返回带编号的文本块补丁，用户可以逐项应用、忽略，或批量应用通过事实保护的项目；旧的整篇覆盖入口不再可用。
- 每条补丁必须逐字带回原文。应用时如果原文已经被用户改过、正文存在多个相同片段，或日期、数字、产品名等事实锚点丢失，系统会停止自动覆盖。
- 应用前自动保存当前版本；未接受的标题、段落、列表、链接、图片和图注不会被重建。

这些能力借鉴了 MIT 许可项目 [md-wechat](https://github.com/laogou717/md-wechat) 的图片入口、实时排版预览和富文本复制思路；连续编辑器保持平台中立，由小黑盒和微信公众号适配器分别执行交付检查。

## 本地启动

需要 Node.js 22.16.x（仓库通过 `.node-version` 和 `package.json` 锁定）及 npm 10.9.x。仓库已包含跨平台 RSS、Atom 和 Hacker News 采集器，不再依赖 Mac 上的外置 Horizon/Python 路径。

```powershell
npm ci
npm run dev
```

访问 <http://127.0.0.1:4317>。

生产模式先构建再启动；`npm run start` 已使用跨平台环境变量写法：

```powershell
npm run build
npm run start
```

## 微信公众号草稿箱

1. 登录微信公众平台，在“设置与开发 → 基本配置”取得 AppID 和 AppSecret，并把运行本工具的当前出口 IP 加入公众号 IP 白名单。
2. 打开“定时任务 → 微信公众号草稿箱”，填写公众号名称、默认作者、AppID 和 AppSecret，点击“保存并测试”。连接测试只读取草稿数量，不创建草稿。
3. 在文章草稿右侧打开“发布”，选择“微信公众号”。正文中第一张已插入图片会作为封面；资料托盘中未插入的图片不会上传。
4. 检查作者、摘要、原文链接、事实证据和每张图片的微信使用许可，然后点击“同步到公众号草稿箱”。图片会在本地转成微信可用的 JPG 并压缩到 1 MB 内。
5. 首次同步创建微信草稿；再次同步会更新同一个 `media_id`；本地内容未变化时会跳过上传。最后登录微信公众平台预览并由你手动发布，再回到工作台点击“我已在微信后台发布”。

AppSecret 只保存在本机受保护存储中：macOS 使用钥匙串，Windows 使用绑定当前用户的 DPAPI 加密。它不写入 `.workflow/state.json`，也不进入导出备份。项目没有实现发布或群发接口。

## 安装为 Windows 后台任务

在 PowerShell 中执行以下脚本，可注册当前用户登录后自动启动的计划任务：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-windows-service.ps1
```

打开控制台和卸载自动启动任务：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\open-dashboard.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-windows-service.ps1
```

卸载只移除计划任务，不删除 `.workflow/` 中的新闻、草稿或图片。

计划任务直接托管唯一的 Node 服务进程，在进程临时退出后会每分钟重启，最多三次；同一时间只允许一个实例。后台日志单文件达到 5 MB 后轮换并保留三份历史日志。

## 安装为 Mac 后台服务

后台服务能保证登录 Mac 后自动运行，控制台中设置的每日心跳时间才会持续生效。

```bash
./scripts/install-mac-service.sh
```

以后可双击 `scripts/open-dashboard.command` 打开控制台。卸载时运行：

```bash
./scripts/uninstall-mac-service.sh
```

卸载只停止服务并把 LaunchAgent 配置移到废纸篓，不删除新闻、草稿或图片。

## 小黑盒填入助手

默认使用你日常登录的 Chrome：在 `chrome://extensions` 加载项目内的 `chrome-extension/` 后，草稿页会通过本地桥接把内容送进当前小黑盒编辑器。CDP 隔离浏览器只保留为开发调试备用。两种方式遇到验证码、登录失效、编辑器改版或找不到控件都会停止，不绕过限制，也不自动发布。

## 本地数据

- 运行状态、来源、Story、草稿和任务：`.workflow/newsdesk.db`（SQLite WAL）
- 首次迁移前只读回滚文件：`.workflow/state.json`
- 数据库快照与可移植归档：`.workflow/backups/`
- 旧 Codex 任务包与结构化输出：`.workflow/jobs/`
- 下载的来源图片：`.workflow/media/`
- 可复用图片素材：`.workflow/materials/`
- 后台服务日志：`.workflow/logs/`
- Horizon 原始运行：`.prototype/horizon/data/mcp-runs/`

这些运行数据默认不会提交到 Git。

## 图片原则

- 默认只使用官方页面、原报道页面或网页截图。
- 不生成图片，不拿旧模型或无关品牌图凑数。
- 每张图片保留来源页和署名；公开可访问不等于可转载，发布前仍需检查授权。
